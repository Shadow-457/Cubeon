# You are developing and testing against Flet 0.86.x, so that is what this
# pins. The old `<0.29.0` cap was wrong - it excluded the version actually
# installed, which meant a fresh `pip install -r requirements.txt` on someone
# else's machine got a different Flet than the one Cubeon was tested on.
#
# The upper bound matters more than usual here. On 0.80+ Flet's transport calls
# asyncio.Queue.put_nowait() from whatever thread invoked page.update(), which
# does not wake the event loop - so background-thread UI updates silently
# vanish until stray input wakes it. cubeon/thread_safe_ui.py works around that
# by marshalling updates onto the loop. If you raise this bound, re-check that
# workaround still applies (and still finds the loop) before shipping.
