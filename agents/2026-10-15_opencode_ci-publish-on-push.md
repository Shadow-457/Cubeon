# 2026-10-15 — CI: publish Windows + macOS to the release on push

**Asked:** "make it that when i push it create new windows exe and macos file
and push them to the latest release" → main only, exe + macOS, AppImage is
built by hand.

## What changed (`.github/workflows/build.yml`)
- A push to **main/master** now rebuilds **only Windows + macOS** and refreshes
  the repo's **LATEST** release in place (`gh release upload … --clobber`).
  Tag pushes behave exactly as before (own tag release).
- The target tag is resolved at run time with
  `gh release view --json tagName --jq .tagName` — whatever GitHub marks
  Latest (currently **v1.1.2**), so it follows future releases instead of a
  hardcoded name.
- The Linux **AppImage job is skipped on branch pushes** (maintainer builds it
  locally); it still runs for tags + `workflow_dispatch`.
- `actions/upload-artifact` steps stay tag-only (they count against the Actions
  storage quota; release assets do not).

## Two CI failures I found and fixed (both pre-existing, both blocking the exe)
1. **Test suite failed** on every push: `tools/test_mega_smoke.py` did
   `open("Cubeon.spec")`, but `Cubeon.spec` is a **gitignored** PyInstaller
   byproduct (regenerated by `--name Cubeon main.py`), so a fresh checkout has
   none → `FileNotFoundError` killed the whole suite. Now the spec assertions
   run only when the file is present (prints a skip line otherwise).
2. **Windows build failed**: `choco install nsis` puts `makensis` in
   `C:\Program Files (x86)\NSIS` but does **not** refresh PATH inside the
   running job, so `build_windows_installer.py`'s `shutil.which("makensis")`
   came up empty → "NSIS not found" after the ZIP had already been built. The
   `Install NSIS` step now appends that dir to `$GITHUB_PATH` (locating it via
   `Get-ChildItem`, throwing if absent). Also split the build so the **portable
   ZIP publishes before the installer step**, i.e. the exe still ships even if
   NSIS breaks again.

## Verified
- `python3 -c "import yaml; yaml.safe_load(...)"` → YAML OK, step lists sane.
- `tools/test_mega_smoke.py --static` → 16 passed / 0 failed *with* the spec;
  **15 passed / 0 failed with the spec moved away** (the CI case) and it prints
  the skip instead of crashing.
- `tools/test_mega_smoke.py --suites` → **42 passed, 0 failed**.
- **Live proof the pipeline works:** the a9fcaa6 push (first run of this
  workflow) refreshed `Cubeon-macOS.zip` on v1.1.2 to 16:20Z — the macOS half
  published. The Windows assets stayed at 00:07/00:13Z because of failure #2.
- **Fully green after the fix:** run `38769059117` (push 0ac5826) →
  Test suite ✅, Build Windows EXE & ZIP ✅, Build macOS app ✅,
  Build Linux AppImage skipped. v1.1.2's assets then read
  `Cubeon-Windows-x64-Setup.exe` 16:30Z, `Cubeon-Windows-x64.zip` 16:29Z,
  `Cubeon-macOS.zip` 16:28Z (Linux assets untouched). The NSIS installer
  build worked once makensis was on PATH.

## Note
Pushing to main **overwrites the latest release's assets with an untagged
build**. That is what was asked for, but it means the "Latest" release is not
necessarily the tagged commit any more.
