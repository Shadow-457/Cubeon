# Cubeon module map

Read this first, then only the references needed for the task. Public guides live in
[docs/](../../docs/README.md). Detailed earlier findings are preserved in [the implementation
reference](../history/implementation-notes-2026-10-24.md); dated or superseded entries there are not a
substitute for current code.

Tabs are retained. Mods, Modpacks and Servers control trees warm after first paint; catalogue requests
remain on demand. Other lazy builders stay lazy. Shared state and callbacks are wired in `main.py`;
keep builders consistent with the shared `THEME` contract.

## Contracts to preserve

### Flet and UI updates

- Dependencies pin Flet and `flet-desktop` to `>=0.86,<0.87`; a machine-wide installation of another
  version is not the release environment.
- `python main.py` verifies matching 0.86.x packages before any UI/package import;
  `source_runtime.py` can re-exec a verified checkout `.venv` or `.venv-build` (isolated,
  bounded metadata probes), otherwise prints local setup commands. Frozen builds skip it.
  All client-crash recovery uses fresh interpreters: pre-paint and mid-session failures
  share the two-restart `CUBEON_GPU_RESTARTS` budget and llvmpipe → softpipe ladder;
  the inherited count enables fallback even if the marker could not be written.
  Explicit GTK/EGL/Mesa environment choices bypass automatic rendering changes,
  even with a stale software marker. `incident.capture_rendering_overrides()`
  runs before fallback and retains `CUBEON_USER_RENDERING` across interpreter
  replacements, distinguishing user choices from automatic retry values.
  Unsetting WAYLAND_DISPLAY in a Wayland session with DISPLAY also opts out.
  Both Java and Rust game children drop that internal flag.
  On frozen Linux, `incident.client_environment()` restores LD_LIBRARY_PATH_ORIG
  (or clears the bundled path when absent) for native Flet, Java and Rust
  children. Apply it to the final game environment, including an explicit
  native backend environment. Their engines resolve their own libraries;
  GTK/EGL/GLX/Vulkan must use host dependencies. v1.4.1's Jammy-bundled libstdc++
  and OpenSSL reproduced GLX/Vulkan loader failures on Arch/Mesa 26.1.6 when
  inherited by native children. `test_game_environment.py` covers real child
  inheritance for the default and explicit game environments and Rust preparation.
  Never change the frozen Python process's library search path for this fix.
  Never call `ft.run` twice after a failed first frame. `test_source_runtime.py`,
  `test_startup_recovery.py` and the real-process wedge test cover these contracts.
- Mutate shared control trees under `thread_safe_ui.TREE_LOCK`; request scoped repaints through
  `thread_safe_ui.refresh()`. Background threads must not invoke a whole-page update directly.
- Chat polling reads connection/events/history and updates service viewing/read state outside
  `TREE_LOCK`. Socket lifecycle callbacks can deliver launcher notices that need that lock;
  reading `roster_payload()` while holding it deadlocks connection updates. Keep control
  mutations locked; `tools/test_chat_poll_locking.py` reproduces the opposing lock order.
- Apply saved window geometry before revealing the branded splash. `_reveal_window()` only
  reapplies geometry as an interrupted-setup fallback; never recenter the visible finished UI.
  Do not map Linux windows with native `window.opacity=0`: GTK can stall waiting for frames.
  Entrance/page fades use control opacity, with the existing motion preference.
- Startup replaces the splash as soon as the shell is ready; do not add a
  minimum display delay. Keep the initial 120 ms paint yield, awaited native
  reveals and hidden-window geometry ordering. Initial version-list population
  reuses `_initial_versions`; later refreshes rescan. Settings' passive Java label
  is populated by the post-reveal `cubeon-java-warm` worker through TREE_LOCK and
  a scoped repaint: `find_java()` runs executable probes with 8-second timeouts
  and must not run while building the splash/UI. Play retains its own verified
  Java selection. Optional `detected_java_label` preserves existing Settings callers.
- Idle daemons block on an Event, they do not sleep-poll: `main._bar_loop` waits on `_bar_wake`
  (set by `set_bar`, the only thing that starts a progress animation) and `_wedge_watchdog` waits on
  `_wedge_wake` (set by `_wedge_arm`). Each clears its event *before* re-reading the state, so a
  wake landing mid-check cannot be lost. Do not add a timeout-poll "just in case" - show the bar
  through `set_bar()` (`progress_bar.visible = True` alone no longer wakes the ticker).
  `tools/test_bar_idle_wake.py` and `tools/test_idle_wakeups.py` guard this.
- Linux RAM comparisons should include the Python payload, native Flet client and AppImage wrapper;
  use `/proc/<pid>/smaps_rollup` PSS for proportional shared-memory accounting rather than summing RSS.
  Sandboxed `ps` may see only its own PID namespace; host inspection needs approval. A single
  startup/warm-up snapshot does not establish a leak or attribute specific image/control allocations.
- CPU verification must include both Python and the native Flet process; divide summed core CPU
  percent by logical CPU count to compare with Windows Task Manager. The 2026-10-29 native Linux
  probe (Flet 0.86.5, offline metadata) measured ~1.7% total idle with the pet, ~0% minimized or
  decorations off. This does not certify Windows/Defender behavior. `test_wedge_watchdog.py` needs
  local socket permission and isolates home paths before imports and cleanup scans with test assets.
  For Linux resource experiments, a systemd user scope's MemoryMax applies to the launcher and
  inherited Flet/Java children together, not the OS. Use taskset for verified CPU affinity:
  AllowedCPUs alone did not restrict this user's scope. CPU/RAM caps do not emulate Intel iGPU
  throughput; FPS certification requires the actual target GPU.
- New configs default `seasonal_theme=False`, so first startup uses green and onboarding's
  seasonal switch starts off. Onboarding/replay reads the saved choice; preserve explicit
  enabled preferences and existing command-line/environment palette overrides.
- `SeasonalAnimator` (one daemon ticker, `TICK = 0.12`) has `pause()`/`resume()` backed by a
  `threading.Condition`; `main._on_window_event` pauses on `minimize`/`hide`/`blur` and resumes on
  `restore`/`show`/`focus`. Do not implement this with a `threading.Event` and `event.wait()` while it
  is SET - wait() returns immediately and spins a core. Measured: 8.3 frames/s minimized before,
  ~0.3/s after (only the in-flight frames around the event). `tools/test_seasonal_animator_pause.py`
  guards both the gate and the event wiring.
- Play's seasonal overlay uses uniformly scaled bundled RGBA trees (including
  the tilted sapling), a ground strip and at most 12 small sprites (nine autumn
  leaves), advancing every other shared tick (~4.17/s). Seasonal look and the
  independent `season_overlay` (Play scenery) preference enable it; Full motion
  controls particles, with no Weather effects setting or layout band. Hidden
  Play panes drop their shared ticker registration;
  an empty ticker blocks on its Condition and only session-end joins it. In pinned
  Flet, bind `on_size_change` to the **inner non-positioned Stack**, never the
  positioned overlay Container: its notifier otherwise breaks Flutter parent data
  and produces a gray ErrorWidget. The host ignores interactions; artwork stays
  behind Play controls. `tools/test_play_seasons.py` covers geometry/gates/assets;
  `tools/capture_play_seasons.py` verifies painted native artwork and live resizing.
- `LauncherPet` mounts in `page.overlay` before dialogs, not a wrapper Stack
  around the app Row (that breaks the Play artwork in native Flet). It reuses
  one sprite and ticker; resting/reduced/paused states use bundled PNGs instead
  of decoding GIFs. `switch_tab()` anchors it to the floor **before** painting
  the pane swap and includes its host in that repaint. Play perch y derives
  from the current footer layout (`window height - 287 - 32`); update and test
  that contract if the footer moves. Small windows retire unavailable perches.
  `tools/test_launcher_pet.py` covers routes, tab swaps, resize and motion gates.
- The flet desktop client prints `'FlutterEngineRemoveView' returned 'kInvalidArguments' ... the
  implicit view cannot be removed` (plus, on 0.86, two `FlBinaryMessenger without an engine` GLib
  warnings) on **every** window close. It reproduces in a 12-line vanilla flet app on 0.86.5 and
  1.0.3, so it is client-side, not a Cubeon failure. `main._CLIENT_TEARDOWN_NOISE` drops those lines
  from the forwarded client stderr (they still land in `_client_tail` for incident records). Do not
  "fix" it by skipping `page.window.close()`: that is what leaves the ghost client `_kill_flet_client`
  exists to end.
- `WindowCloser` owns custom-X and restart close requests. It deduplicates queued/inflight calls and
  treats only exact `RuntimeError("Session closed")` as successful teardown; other failures stay logged
  and retryable. Never schedule the bare `page.window.close` coroutine. Reported disposed FlView/widget/
  compositor diagnostics are quiet only while `_client_closing` is set, and stay in `_client_tail`;
  the same messages during a live session remain visible. `test_window_close.py --native` opens and
  automatically closes isolated probes on both installed Flet versions (requires a GUI).
- Use `cubeon.dialogs` for dialog-stack compatibility. Removed APIs include `ft.border.all`,
  `ft.padding.only`, and `ft.margin.only`.
- `theme.keyboard_target` adds native Tab/Enter/Space and focus outlines over custom button
  artwork while retaining the original control/handlers for scoped repaint. Forward events with
  the original control; preserve its tooltip, dimensions and disabled action gate. Play mode
  changes also synchronize its keyboard target's disabled flag, tooltip and accessible label.
  Pinned Flet's animated `Container.ink` path double-applies padding; do not use it for these
  targets. Native `Semantics` requires a content control, even for a transparent button.
- Global navigation/Play shortcuts are blocked behind managed dialogs, onboarding, the version
  picker and Settings. Escape dismisses the top dialog, then panels, then fullscreen; F1 toggles
  its own help. Settings uses the retained tab host, with independently scrolling
  rail/content. `tools/test_keyboard_accessibility.py` covers action gates, help
  Close, Settings navigation, and typing punctuation in Chat.
- Launcher notices route through `ui/toast.py`. Its stretched accent/body Row needs
  `intrinsic_height=True` inside the shrink-wrapped Column; without it native Flet
  produces an invalid transform and invisible cards. New overlay hosts must repaint
  `page._overlay`, not the unattached host. Deduplication is per window; eviction/close
  releases persistent notice waiters. FriendsService's optional `set_notice_handler`
  pushes new events to the current launcher session outside its ring lock, without
  network polling or replay; `main.py` binds it and unbinds on teardown.
- Optional `ui_sounds` stays off by default. Bundled launch/error WAVs play on one daemon with
  a 2s cooldown; off returns before filesystem/backend work. Configure with the live config and
  resolved assets after installing toasts, clear on teardown. Uses Windows winsound, macOS afplay,
  or Linux paplay/aplay when available; subprocess playback is bounded to 2s. No added dependency,
  network or polling. `tools/test_ui_sounds.py` verifies defaults and concurrency bounds.
- `cubeon/render_compat.py` implements the opt-in rendering Apply/Restore helper
  (its former Settings → Fix problems entry is removed),
  scoped to the selected instance (`game_dir_for(..., create=False)`). It bypasses
  EntityCulling entity/block/tick culling and ImmediatelyFast enhanced batching only
  for existing known config keys. Originals are backed up before changes; restore
  preserves later user edits. Normal launch never enables this workaround. Culling/
  batching reports do not prove a user's exact cause, and FPS can decrease.
- Local absolute paths are not valid `ft.Image.src` values. Use cached base64, bundled asset paths, or a
  real URL; do not restore blank local images.
- `scrolling.follow_end` owns its coroutine completion and skips hidden/detached ancestors.
  Only the exact native `scroll_to` listener timeout and session/detachment errors are quiet;
  unrelated failures must propagate. Scheduling bare `ListView.scroll_to` lets Flet re-raise
  asynchronous listener timeouts from its Future completion callback.
- Reuse installed/browse rows and image controls during metadata updates; chat presence must not remount
  PFPs, and sources change only with real artwork.
- Default hover/click effects are fill/rim fades, not scale or corner morphs; Mods and Modpacks do not
  replay cascade/shimmer animations on refresh.
- Rows with expanding spacers must not use `wrap=True`; Flutter's wrapped layout cannot host flex
  children. Check actual rendering, not only Python builds.
  Settings' backup actions use two expanded buttons in an unwrapped Row and a separate restore row;
  the history text has a flexible wrapper. Wrapping the expanded buttons caused the gray error panel.
- Tab loads repaint their own region: `ui/mods_tab.py` and `ui/modpacks_tab.py` browse loading,
  cached-page render and content-type switches use `thread_safe_ui.refresh(...)`, not `page.update()`.
  A whole-tree diff in the same moment a tab is built/fetched was the "clicking Mods stalls the app"
  hitch. `tools/test_tab_repaint_scope.py` counts the full updates and fails on one.
- The Server tab follows the same rule: `set_running_ui` refreshes `console_view` + `settings_view`
  (everything it mutates lives in one of them), and `refresh_whitelist_list` / `refresh_orphan_notice` /
  `refresh_plugins_visibility` / `tagged_dropdown`'s `sync_color` refresh the controls they changed.
  Opening Servers used to cost 9 full diffs (now 1, the tab switch). If a helper starts mutating a
  control outside those two columns, refresh it there too - `tools/test_server_repaint_scope.py` proves
  each mutated control is inside a repainted region.
- Instance selection is a scoped repaint too: `update_hero()` refreshes `hero_title`,
  `hero_version_text`, `hero_loader_chip_text` and `version_issue_text` itself. Do not add a
  `page.update()` to the row-click path to make a new hero label appear.
- Navigation requests Server and Modpacks metadata snapshots through `background_refresh.py`:
  reads run outside `TREE_LOCK`, application runs inside it, and only the latest generation paints.
  Server selection/edit guards preserve user changes; public-address scans read only the final
  256 KiB of the log. Do not restore synchronous backend reads to the tab-switch path.

### Navigation shell

- The nav is a fixed **92 px left icon rail**: `_build_sidebar()` builds fixed-size tiles,
  icon over label; `nav_blob` slides vertically. The nav area scrolls above pinned Settings,
  so short windows remain usable. The seasonal pet uses the page overlay. The previous resize grip is gone.
- `top_bar` is the **brand strip** (cube mark + wordmark, moved out of the sidebar 2026-10-26) and, under
  the custom frame, the title bar. It is 44 px; Account lives on the right, and the min/max/close cluster rides it only when
  `_custom_chrome` is on. `ft.WindowDragArea(content=top_bar, ...)` is load-bearing for the smoke test.
- `switch_tab()` runs under `thread_safe_ui.TREE_LOCK` and sets **every** cached `_tab_views` pane to
  `visible = (k == key)`; hiding only the previous pane let a raced/worker transition leave two tabs on
  screen (2026-10-25). Paint the swap before per-tab refreshes; build lazy tabs before mounting.
  The new pane fades over `motion.BASE` (180 ms) without remounting cached controls or images.
- The hero PLAY click has a 0.35 s `_PLAY_CLICK_COOLDOWN` gate so a rapid double-press cannot run the
  username/config/Java pipeline twice; CANCEL/QUIT bypass it. A click that returns `False` releases the
  gate immediately (only a click that started work keeps it).
- The 300×64px Play action uses `assets/pixel_button_frame.svg` with bundled Inter bold action labels
  (small Minecraftia glyphs distort under Windows DPI/font rendering);
  keep frame/label descendants inside the clickable container and retain semantic fills. Flet 0.86
  mode changes must assign `play_button_icon.icon` (a `.name` assignment never updates the glyph).
  Set its width before `theme.keyboard_target` copies the dimensions; the aligned action host
  never expands in the wide input Row and keeps the same button width in compact layouts.
  Busy repaints derive `CANCELLING...` from the installing version's armed cancellation Event,
  so tab/selection refreshes cannot restore an enabled Cancel before worker acknowledgement.
- A launch has three ordered claims: `installing_version` (cancellable install) → `launching_version`
  (install done, game not spawned) → `running_version` (process live). `set_button_mode("play")`,
  `_main_action_click`, `on_play_click` and `_begin_install_and_launch` all honour them, so a repaint
  inside the handover window cannot show PLAY or start a second game. `launching_version` is set under
  `_launch_state_lock` when `installing_version` clears and released in the worker's `finally`.
  It remains claimed through all backend setup; only successful spawning hands it to the actual
  `target_version`. Spawn/exit UI uses lock order `TREE_LOCK` → exit lock → launch-state lock.
  Per-launch liveness Events wake on exit and retire the previous watcher; do not suppress a new
  watcher because an older same-named thread is still alive.
- Quit owns `state["ending_session"]` until its worker reconciles watchdog liveness, on success or
  failure. Recovered games have no `on_exit`, so termination must restore the button itself. Optional
  playtime/log/presence cleanup must never prevent the exit callback or hold the UI tree lock.

### Play and content

- `content.content_mc_versions` includes both 1.20 and 1.20.1 tags for packs/shaders
  (shared resource format 15); 1.20.0 maps to that pair. Modrinth's exact 1.20 search
  index returns no hits despite project releases listing it. Browse, download and detail
  compatibility share this rule; mods and instance/profile IDs keep their exact versions.
  Search/download cache keys include candidate tags so old empty exact-filter results cannot hide fixes.
- Mods/Modpacks use static skeletons from `ui/content_states.py`, with no shimmer daemon.
  Preserve existing rows/artwork while refreshing. Modpacks merges both providers regardless
  of completion order, retains healthy partial results, and offers Retry for failed empty
  results; stale generations cannot replace a newer search. Covered by
  `tools/test_content_search_recovery.py`.
- Mods uses cached per-instance snapshots: the main callback requests
  `refresh_mods_list(background=True)` and filesystem/archive reads run outside
  `TREE_LOCK`. Filters/counts/badges reuse snapshots; captured row/file-picker/
  download targets survive selection changes. Browse must cache its page before
  applying the installed snapshot, or that repaint can launch a duplicate fetch.
  Installed rows expand in 25-item batches and detail versions add 25 at a time.
- Local mod import is an offline batch review (`local_mods.review_files`) before
  writes: validates archive/descriptors, loader/Minecraft version, server-only
  builds and protected identities. Exact hashes skip duplicates even after a
  rename. Replacements are opt-in, preserve old files/sidecars disabled, and
  recheck preview hashes/installed conflicts before staged publication/rollback.
  `ui/local_mod_import.py` owns selection/results; file picking and imports retain
  the captured instance. No automatic network repair runs during local import.
- Resource-pack/shader switches rename only the profile entry to/from `.disabled`;
  launch staging skips these files/folders, while shared store bytes and sibling
  metadata survive. Enabled means available at next launch, not selected in game.
  `file_safety.py` validates filenames and profile/store containment. Prepare
  repairs before store publication; detach directory links before folder repairs.
  Adoption retires originals only after profile linking succeeds. Staging records
  successful publication or retained ownership after a failed removal, never a
  desired-but-unpublished filename. The two management-audit suites cover this.
- Content and mod downloads validate every redirect with the mrpack host allowlist,
  use unique temporary files, and clean `.part` failures. Mod cache hits verify
  requested hashes as well as SHA-256, memoized by file stat signature. Descriptor
  reads cap at 1 MiB; nested mod scans cap individual JARs at 64 MiB and cumulative
  nested bytes at 128 MiB/256 entries, opening the top-level JAR from disk.
- Modpacks artwork construction uses memory-only `icons.peek_src()` or the bundled placeholder.
  `icon_loader.IconLoader` coalesces URLs with at most four workers and 128 outstanding URLs;
  download/file/base64 work stays outside `TREE_LOCK`, with stale URL guards at application.
  Expanded lazy ListViews scroll the rows; provider pages cap at ten each and installed rows
  build in batches of 25. Initial skeletons use `fill=BORDER` and stay enabled: disabling the
  loading list makes native Flet dim the skeleton until it is effectively invisible.
- **The version picker** is the one instance surface (2026-10-26): a right-hand slide-in panel
  (`ui/versions.py`, in `page.overlay`) with a 2-column grid of bundled SVG block/mob icons,
  title + subtitle below. The pencil chooses from 20 blocks and 20 mob heads in the same panel;
  `cubeon/instance_icons.py` validates IDs and `cfg["instance_icons"]` persists them per instance.
  A 32px upload icon in the existing Blocks/Mob heads row accepts PNG/JPG/WebP/GIF
  for edits and New Instance setup. `main._upload_instance_icon` lazily reuses
  one version-safe FilePicker; decoding/copying runs on a worker. Imported images
  become transparent, uncropped 128px PNGs or animated GIFs in `CUBEON_HOME/instance_icons`, identified
  by `custom-<SHA256>` rather than source paths. Cached base64 sources work after
  the original moves; missing stored images fall back to bundled icons. Cancelled
  and stale panel completions cannot replace another instance's selection.
  GIF normalization retains composited frames, durations, transparency and loop count;
  imports are bounded to 500 frames/64M source pixels/2MB output. The base64 cache
  has 32 entries. The existing close-fade timer hides the icon list/category row
  after closing so animated icons retire while the panel's slide host stays mounted.
  `tools/gen_instance_icons.py` generates the 40 SVGs. Selection never changes when choosing an icon.
  Folder/Rename/Delete live on the Play card. "New instance" defaults to Fabric on every new flow
  and has three separate steps: loader →
  compatible Minecraft version → block/mob/custom icon. Back preserves choices; only final Download & Play
  commits through `main._create_new_instance`. The icon is saved to the resulting loader instance ID,
  never a sibling vanilla version. Opening New Instance starts Mojang/default-loader discovery
  concurrently during the loader step; Next reuses completed or in-flight requests.
  Mojang and loader support catalogues cache for 1h and serve expired data immediately while
  refreshing in the background. Cold reads use pooled `net` requests with 5s timeouts and one
  attempt per endpoint (both Mojang mirrors remain available); per-catalogue locks coalesce
  simultaneous cold reads. `tools/test_versions_manifest.py` and `tools/test_new_instance_steps.py`
  cover cache behavior, support parsing and setup preloading without live network/native windows.
- Legacy and loader support are separate gates: opting into Legacy includes old alpha/beta manifest
  rows and permits 1.8 Vanilla; Fabric still only offers its supported versions. New instance excludes
  existing installs (including 1.8.9); searched empty lists explain an installed version or incompatible

- `CubeonHudConfig` stores one size per overlay (`fpsScale`/`keysScale`/`armorScale`/`pingScale`/

  both keep their meaning. Read sizes through `scaleFor(slot)`/`CubeonHud.scaleOf(overlay)`; never apply
  `scale` directly. `resetPositions()` also resets sizes to 1.0 (it is labelled "Reset Positions & Sizes").
- K → Configure uses a 0.50–2.00× size slider, with 0.01 keyboard adjustments and live per-overlay updates.
  `setScaleForLive` never writes files; slider release/navigation/close saves the drag once.

  MoveOverlayScreen explicitly previews the selected widget and other **enabled** HUDs through
  `CubeonHud.renderPreview` at their independent positions/scales; muted frames turn amber on overlap.
  Do not re-enable normal HUD callbacks in the editor, mutate peer visibility or duplicate selected draws.
- Each overlay pushes its own matrix around its own draw (`CubeonHud.renderOverlay`) and divides its
  screen position by that same scale. A single transform around the whole HUD is wrong now: it would scale
  every widget by one overlay's size. Three matrix spellings exist by era (`getMatrices().push()` +
  3-arg `scale` through 1.21.5, `pushMatrix()` + 2-arg from 1.21.6, `pose().pushMatrix()` on 26.x).

  `showArmorMainHand`/`showArmorOffHand` fields.
- Freelook is camera-only on all 24 brackets: rebindable Left Alt holds a rear orbit,
  mouse rotates independent yaw/pitch and wheel chooses 1–12 distance (up nearer, down farther).
  Release restores the saved first/rear/front perspective; menus, focus loss, death/sleep,
  owner/world changes and F5 stop it. Interrupted holds need release before resuming; F5 wins.

  or send rotation packets. Yarn `freelook-yarn` reuses the existing `ZoomLookMixin` redirect

  `clipToSpace` input, preserving raycasts/entity scale. Both HEAD boolean modifiers share a
  managed-view flag cleared at RETURN so release fixes stale caller arguments in either order.
  All 26.x use `freelook-mojang`: Camera.update(DeltaTracker), alignWithEntity/setRotation,

  `--targets` additionally audits every cached mapped game JAR. Builds/bytecode checks do not
  replace a real in-game recording test with other camera mods installed.
- Hold-to-zoom uses `zoom-double` for 1.20-1.21.1 where `GameRenderer.getFov` returns `double`,
  `zoom-float` for 1.21.2-1.21.11 where it returns `float`, and `zoom-26.3` on 26.3.

  `FreelookLookMixin` redirect; `${zoom_look_mixin}` omits a competing ZoomLookMixin.

### Windows, Java, and packaging

- Linux release packaging is pinned to `ubuntu-22.04`; do not restore a rolling
  runner without checking CPU and glibc baselines. The 2026-11-06 v1.3.54 download
  crashed on a Xeon E5-1650 at libpython3.11+0x2b5b5f: `vinserti128` in
  `pymem_set_default_allocator` requires AVX2, before any Cubeon code runs.
  `runtime_probe.py` / `--cubeon-runtime-check` exercise native runtime libraries
  without UI/user data. `tools/check_linux_runtime.py` runs the frozen executable
  under QEMU Nehalem in CI (`CUBEON_REQUIRE_CPU_CHECK=1`) before appimagetool;
  local builds without QEMU test only the host CPU. This is a packaging/runtime
  baseline failure, not evidence of Java, GPU or instance-storage corruption.
  Build isolation uses absolute `CUBEON_BUILD_DIST` / `CUBEON_BUILD_WORK`, including
  the spec/cache; PyInstaller data inputs must remain absolute with that spec path.
- The launcher auto-updater is removed. Startup performs no release checks;
  Settings has no update channel/check control or Cubeon update notification
  switch. `cubeon/updater.py` retains only the literal APP_VERSION for release
  stamping, installer resources and HTTP identity. Launcher upgrades are manual
  through the download page and existing platform installers. No replacement
  update system has been implemented.
- `storage.application_busy(state)` owns the storage-migration UI gate for
  active games, installs, session teardown and hosted servers. It treats failed
  ownership probes as busy and runs outside TREE_LOCK; the backend migration
  keeps its independent idle validation. It has no updater dependency.
- Windows distribution is installer-only: `packaging/build_windows.py` produces the internal onedir payload
  (`Cubeon.exe` + `_internal`), NSIS stages and swaps it with rollback, and the workflow publishes
  only `Cubeon-Windows-x64-Setup.exe`. Do not restore ZIP/single-file/public portable builders.
  NSIS resolves InstallDirRegKey and `/D` before `.onInit`; do not override that directory again.
  `/D` is last and unquoted. Uninstall removes only owned program entries and only clears registry/
  shortcuts for that registered copy. `test_launcher_installers.py --wine` tests install, upgrade,
  preserved timestamps, custom directories, incomplete-payload rejection, and data-safe uninstall.
- NSIS must leave the staged runtime tree before moving it; Windows keeps the
  current directory open. Program swaps use native MoveFileW with bounded
  retries for errors 5/32/33 and preserve backups on rollback failure. Setup
  records the phase/path/native code in `Cubeon-Setup.log` beside the installed
  executable. NSIS `FileOpen ... a` requires `FileSeek ... END` to append.
  Installer regressions cover file locks, rollback, recovery bytes and empty
  runtime directories; `--native-windows` runs on the disposable Windows build
  runner before publishing. Wine does not faithfully enforce directory locks;
  its fixture uses actual file handles to verify sharing violations.
  Native test launches must pass NSIS a raw Windows command line with `/D`
  (or uninstall `_?=`) last and unquoted. A list argument containing an entire
  `cmd /c` command is escaped for the C runtime, which cmd does not understand,
  and can swallow `/S` and hang at the interactive wizard.
- `build_linux_installers.build_setup()` appends an AppImage/icon tarball to the setup script with
  SHA-256 verification. Distribute the complete generated script, not `install_linux.sh` alone.

script first, then the smoke gate.

  discarded after 24h). Every content page carries the HTML snippet

- Website Doctor lives in `web/doctor.html`, with shared rules/evidence validation in
  `web/assets/doctor-core.js` and a server-only Groq → Kilo endpoint in `web/api/doctor.js`
  (root `api/doctor.js` wrapper). Set `GROQ_API_KEY` and `KILO_API_KEY` in hosting secrets, never browser code.
  Each request picks uniformly from `D.GROQ_MODELS`, with one 15s Groq attempt, then up to two
  Kilo `kilo-auto/free` attempts inside a shared 52s deadline. Any Groq failure advances to Kilo;
  terminal Kilo errors stop its retry. Missing Groq configuration keeps Kilo-only deployments working.
  File upload starts AI; paste requires Analyze. Launcher `/doctor#report=` transfers are redacted,
  compressed and consumed before requests, and stay local until Analyze. Instructions render as a
  safe Markdown subset, with no raw HTML or mock UI. Quotas/failures retain the on-device result.
  Local mod attribution uses explicit loader ownership/failure sections or suspected mods,
  never loaded-mod lists, class packages or mixin filename prefixes; ambiguous owners stay unknown.
  Native allocation failures have separate advice from Java heap exhaustion. Dependency guides
  include up to four conflicts, with Minecraft/Java/loader requirements treated as runtime changes.
  AI failure codes distinguish configuration, credentials, quota, timeouts and invalid guides;
  local `.env` secrets do not reach Production, which needs a hosting secret plus redeployment.
  AI is capped at 3 analysis requests per rolling 30 minutes per address hash **per instance**;
  fallbacks count once, denied requests do not extend the window, and capacity 503s spend no slot.
  Visitor 429s carry scope/retry seconds; shared global enforcement needs hosting/store configuration.
  See `docs/development/website-doctor.md` for size, timeout and instance-local throttling contracts.
