# Seasonal themes — 2026-09-17 (Cline)

What landed: the full seasonal layer. `cubeon/seasonal.py` + `seasonal_geo.py`
detect the user's hemisphere/climate from their timezone (all offline) and pick
one of four new palettes (autumn/spring/winter/summer, --color8..11) at import
time. `ui/seasonal_ui.py` adds the top-bar badge, a season pet (autumn fox,
winter snow golem, spring bee generated by `tools/make_season_pets.py`; summer
reuses the existing parrot), and opt-in ambient particles — all on one shared
animator thread. Settings > Seasonal gets detection status, an override
dropdown, pet/ambience switches, and "Restart to apply" (module-level
`_relaunch["request"]`, honored by the __main__ loop with a clean execv after
ft.run returns). A once-per-season greeting card explains what changed.

How verified:
- `tools/test_seasonal.py` (NEW, 91 checks): meteorological boundaries,
  southern flip, tropics, precedence matrix (env pin/off/auto > config off >
  override > detection > default), palette token completeness + WCAG AA
  contrast, aliases, apply_template. All green.
- `tools/test_ui_smoke.py` 124/124, `tools/test_mega_smoke.py` 16/16
  (both build the real UI headless, including the new Settings pane).
- Not verified live (no display in this session): the actual window look, and
  the restart button's execv path end-to-end. The execv is modeled exactly on
  the tray reopen path and runs after `_kill_flet_client()`, but a human
  should click it once before shipping a release.

Gotchas hit along the way:
- `seasonal.current()` returns a cached resolution set by `boot()` at
  cubeon-package import — tests that change `_pinned`/cfg must call
  `seasonal.refresh()`, not `current()`.
- `resolve(zone=None)` re-runs detection; to test the "OS won't say" default,
  patch `seasonal.detect_timezone` instead.
- Inserting the test file with line anchors mid-loop corrupted it twice;
  lesson: append sections with insert_line at EOF only.

## Follow-up (same day): the pet now WANDERS

in-place hop with a perch-lane wanderer: `build_perch()` builds a 96px clipped
Stack next to the wordmark; `SeasonalAnimator._wander()` drives
rest->walk->turn (fixed 1px/tick amble ~8px/s, jittered 20-46-tick rests,
~4%/tick idle hops, wall turns bounce + mirror via `ft.Scale(scale_x)`).\nWrote it as pixels on `left/top` (ambience-style), never animate_offset.

Verified: sim of 3000 ticks stays in lane, crosses fully, turns both ways,
faces travel direction, rests skip repaints; all three suites green
(test_seasonal 101 / ui_smoke 124 / mega_smoke 16).

Follow-up same day: "the picker does nothing" + invisible snack text.

Follow-up 2: "still goes to autumn every time". Two real findings:
- The full chain (dropdown -> handler -> save -> boot) VERIFIES green with the
  real save_config (probe: open settings, select_section('seasonal'), set
  dropdown, fire on_change -> disk override + boot picks winter). If a pick
  is lost again, suspect the environment, not the handler.
- LIKELY USER CAUSE: CUBEON_SEASON in their shell outranks the config pick by
  design (precedence #1) - every launch is the pinned season and the picker
  looks broken. Now loud about it: seasonal.env_pin() helper, a DANGER
  note in the Seasonal pane (season_pin_note), and an 8s snackbar naming the

  pure stub artifact. Patch core.save_config back to cubeon.config.save_config

Gotchas worth remembering:

  `anim._lock` and DEADLOCKED (30s tool timeouts, mysterious). Call `_frame`

Follow-up 3 - THE REAL ROOT CAUSE of "picker does nothing": Flet 0.86's
Dropdown fires on_select, not on_change. season_dropdown.on_change was a
dead assignment - the handler was correct but never called by the real UI.
Every headless probe had "passed" only because the probe CALLED the handler
directly. Fixed on_select for: season_dropdown (main.py), the mods profile
dropdown (ui/modpacks_tab.py), and the server color sync dropdown
(ui/server_tab.py). app_driver's HANDLER_ATTRS already included on_select,
which is why the mega-smoke never flagged it. tools/test_seasonal.py now has
a static regression guard: no dropdown may assign .on_change, and the season
dropdown must be wired via .on_select.
IMPORTANT LESSON: probe with the REAL event path (fire c.on_select), not by
calling the handler function - calling the handler tests nothing about the
wiring, which is exactly where this bug lived.
Rebuilt the PyInstaller binary (BUILD_EXIT=0), copied to
~/.local/opt/Cubeon/cubeon, boot-verified clean under CUBEON_SEASON=winter
and unset. Suites: test_seasonal 106/0, ui_smoke 124/0, mega --static 12/0.
