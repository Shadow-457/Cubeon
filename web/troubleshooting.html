Crashes and fixes

Most failures are one of five things: Java, memory, a mismatched mod, a locked file, or a graphics driver. This page finds which one you have.

One change at a time

Every fix here is a single change, and the rule is the same one support people use: change one thing, launch, and see. Two changes at once means you learn nothing when it works - and something confusing when it does not.

The launcher won't start

Run it from a terminal and read the error

Double-clicking hides the message that explains the failure. On Linux, start the app from a terminal so the error stays on screen. On Windows, launching Cubeon.exe from Command Prompt shows the same text.

Check for a security block

  • Windows SmartScreen: More info → Run anyway, only for a file from the download page.
  • Antivirus: a fresh build can be quarantined by a scanner that has never seen it. Check the scanner's quarantine list and restore it if it is yours.
  • Linux AppImage: it needs to be executable. chmod +x it, and if the desktop still refuses, start it from a terminal to see why.

Look at the launcher log

The launcher keeps its log at:

~/.cubeon_launcher/cubeon.log

The last few lines are the interesting ones. If the launcher is starting and dying instantly, that file usually says why. Logs explains the rest of the files in that folder.

If a settings file got damaged

Cubeon never silently replaces a readable-but-broken settings file: it copies it aside as config.json.corrupt-<time> and starts from the last good copy. If you have been hand-editing files, look for one of those, and rename it back once you know what broke.

A full reinstall is the last resort, not the first: replacing the app does not change anything in .cubeon_launcher, which is where almost all failures live.

The game won't start

The launcher is fine, the game window never appears, or it flashes and closes. Check these five, in order:

  1. Version and loader. Does the selected instance's loader exist for that Minecraft version? Reinstalling the version fixes a broken install, and takes one press.
  2. Java. Leave Settings > Java on the managed runtime unless you have a reason. If you pointed it at your own, check it is 64-bit and the right major version: 17 for 1.18-1.20.4, 21 for 1.20.5 and newer, 25 for 26.x.
  3. Memory. 4 GB is the default and is right for vanilla. If you set 16 GB on an 8 GB machine, Java fails to start at all - put it back.
  4. Another game already running. Two copies of Minecraft cannot share one mods folder. Cubeon refuses with "another Minecraft window is using these mods" instead of launching a broken game. Close the other window.
  5. Disk space. The version files, mods and worlds all need room. A full disk fails in confusing ways.

If the game starts and closes within a second, there is a crash report - the next section shows where.

Reading a crash

When Minecraft crashes, Cubeon opens a window with the report and three buttons: Doctor, Copy log, and Discord. The report itself is also on disk, in the instance's crash folder:

~/.cubeon_minecraft/crash-reports/

You do not need to read all of it. Two lines carry almost all of the information:

  • Description or The game crashed whilst ... - what Minecraft was doing.
  • The first Caused by: line - which file or class actually failed.

The long list of at ... lines underneath is the call stack. It is useful to a developer and mostly noise to everyone else - except that a mod's name in there is a strong hint about who to blame.

Common crash messages

Find the line that looks closest to yours. "Usually means" is doing real work in that heading - the same text can have more than one cause.

MessageUsually meansDo this
java.lang.OutOfMemoryError: Java heap spaceThe game ran out of allocated memoryRaise RAM one step (6 GB, then 8 GB), close other apps, lower render distance or shaders
NoClassDefFoundError / ClassNotFoundExceptionA required library or mod is missing, or the loader is wrongInstall the dependency the log names; confirm the loader matches the mods
NoSuchMethodError / NoSuchFieldErrorA mod was built for another Minecraft versionSwap it for the build that matches this instance
Mixin apply failed / MixinTransformerErrorTwo mods change the same thing, or one is too oldSwitch off the newest mods and add them back one at a time
Unsupported class file major versionJava is older than the game or the mod expectsUse the managed Java in Settings > Java, or install Java 21
Duplicate mods: ...The same mod exists twice in the folderCheck & repair renames the duplicate; or switch one off
Entrypoint stage 'main' / 'client' failedA mod failed while starting; the next "Caused by" names itRead the cause, switch that mod off, report it to the mod author
EXCEPTION_ACCESS_VIOLATION (often in a driver DLL)The graphics driver crashed, not JavaUpdate the GPU driver, turn off overlays, lower graphics settings

A driver crash is worth saying out loud: an access violation inside nvoglv64, atio6axx or ig*.dll is the GPU driver's own module, and no amount of reinstalling Java will change it.

Using the Crash Doctor

The Doctor page reads a crash log and writes a numbered list of things to try. It works on the report itself, so you do not have to know which line matters.

  • From the crash window: press Doctor. The log opens already attached and redacted, and the on-device instructions are ready without an account.
  • From the website: drop in a .log or .txt file (up to 2 MB). Uploading starts the analysis by itself.
  • Paste instead: expand the log editor, paste the text, review it, then press Analyze log. Pasting never sends anything until you press that button.

The result names the mods, dependencies and settings the log points at, and lists the evidence under See the error lines. You can save the instructions as a Markdown file to keep next to the machine you are fixing.

What leaves your computer

Optional AI analysis uses Kilo's free router through Cubeon's server. The excerpt is shared with Kilo and its selected free provider, which may retain or use it. Redaction removes obvious paths and names but cannot catch everything - delete private details before uploading, or paste and review it in the editor instead. If AI is unavailable, the on-device instructions still work.

Clear removes the log and the instructions from the page. The original file on your disk is not touched.

Crashes with mods

If vanilla launches and a modded instance does not, the mods are the difference. Work in this order:

  1. Press Check & repair in Mods > Installed. It catches duplicates, missing dependencies and version mismatches without disabling anything you did not ask it to.
  2. Switch off what you added last. If the game starts, that mod (or something it needed) was the problem. Report it, or find another build.
  3. Halve the list. Still crashing? Switch off half the mods. Working? The culprit is in the other half. Four or five launches finds almost any single bad mod.
  4. Run the Doctor with the crash report. It reads the "Caused by" chain and usually names the file.

Two failures look like mods but are not: running a pack with a second copy of a library the pack already ships, and installing a mod while the game is open. Both are fixed by the list above, but neither is a bug in the mod.

Slow or stuttering

  • Render distance first. It is the single biggest setting, and the one people forget they raised.
  • Shaders second. A heavy shader pack can cost more than everything else combined. Try the "fast" or "potato" preset before you uninstall anything.
  • Check FPS boost is on. It is the Play-menu switch that installs Sodium and its companions. The benchmarks page shows what it is worth on real hardware.
  • Memory: enough, not maximum. 4 GB is right for vanilla, 6-8 GB for a pack. Beyond that, the garbage collector does more work for no gain.
  • Laptops: make sure the game is on the dedicated GPU and the laptop is plugged in. A power-saving profile ignores most of the above.
  • Close what is behind the game. A browser with 40 tabs is competing for the same memory and GPU.

If it is fine for a minute and then stutters regularly, that is usually memory or world generation, not the launcher. If it is slow from the first second, it is settings.

A world won't load

  • Close the game before copying or deleting a world. Half-written region files are how worlds actually get damaged.
  • Try it on the same instance it was made in. A world that was played with mods may refuse to load without them - the log says which block or entity is missing.
  • Restore a backup. If you made one, this is the moment. Backups shows what Cubeon saves and what it does not.
  • Do not delete the folder yet. A world that fails to load is often still intact; keep the folder somewhere else while you try to open it, rather than clearing space with it.

Reporting a bug

Ask on the Discord for a quick answer, or email hamza.457.shahbaz@gmail.com. A report that gets fixed quickly usually has:

  • your operating system and Cubeon version;
  • what you did, in order, and what happened instead;
  • the crash report or the last 30 lines of cubeon.log;
  • whether it also happens on vanilla.

Before you send a log, remove tokens, identity files, private server addresses and anything you would not post publicly. Which log to send lists the files and what is in them.
