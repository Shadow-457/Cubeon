Modpacks

A modpack is a whole game setup: its own Minecraft version, loader, mods and configs, installed in one go. Here is what that means in Cubeon.

The short version

What a pack installs

Installing a pack does not sprinkle mods into your current setup. It builds a self-contained instance:

  • the Minecraft version the pack asks for, installed if you do not have it;
  • the loader the pack uses - Fabric, NeoForge, Forge or Quilt;
  • its mods, its configs and its overrides;
  • and a Play card for the pack, with its own saves, options and server list.

That isolation is the point: a 1.20.1 pack and a vanilla 1.21.4 world never share a config folder, and installing a pack cannot break a setup you already had.

Expect the download to be large. A pack plus its Minecraft version is often several hundred megabytes, so give it a few minutes on a slow connection and make sure there is room on the disk.

Installing a pack

  1. Open Modpacks. Browse lists packs, Installed shows what you already have.
  2. Open a pack and read its requirements: the Minecraft version and the loader. Cubeon checks those before it starts.
  3. Press Install and watch the progress. You can keep using the launcher; the install runs in the background and the tab tells you which step it is on.
  4. When it finishes, the pack appears as an instance. Select it on Play and press Play.

Only one install can run at a time for the same Minecraft version and loader. Starting a second one for the same pair waits for the first rather than corrupting both.

Packs and your own worlds

A new pack starts with an empty save list. Its worlds live in the pack's own instance folder, so copy a world in only if you mean to - inside an instance shows the folder.

Packs and worlds from an old setup

Cubeon reads the standard pack formats - Modrinth .mrpack and CurseForge packs - and it can pick things up from a Minecraft folder you already have.

Open Settings > Import, choose a folder to scan (an old .minecraft, a backup drive, a downloads folder), and Cubeon lists what it found: mod jars, resource and shader pack ZIPs, modpacks, and world folders (any folder with a level.dat). Pick one and choose which instance to import it into.

Nothing is imported until you pick it, and anything it cannot read is counted and skipped rather than guessed at.

Updating a pack

Install the newer version of the pack the same way you installed the first one. Cubeon:

  • downloads the new version's files;
  • puts them in place before removing anything;
  • then removes the jars the old version owned and the new one does not.

That order is deliberate. If the download fails halfway, you keep the pack you had - a failed update does not leave you with a half-updated, unplayable install.

Two more things it protects:

  • Your settings survive. Existing options.txt and servers.dat are kept rather than overwritten. Other files the pack replaces are backed up under .cubeon-override-backup/ with a timestamp.
  • Your own jars are not pack jars. Jars you added yourself are not part of the pack's list, so a prune does not touch them.

Your worlds are never part of an update. They live in the instance's saves/ folder and stay there.

Removing a pack

Delete the pack's instance from the Play card. Cubeon removes the version folder and the pack marker it owns.

The world folder is a separate thing and is not deleted with the instance. If you want the pack gone completely, delete its world folder too - after you have checked there is nothing in it you want.

Deleting the pack instance does not delete mods you installed yourself, and does not change your other instances.

When an install fails

"Install failed" is the message; the reason is in the log. The usual suspects, easiest first:

  • Disk space. Packs need a lot of it. Free some up and press Install again.
  • The network dropped. Retry - Cubeon re-checks and re-downloads rather than resuming a corrupt file.
  • The same version and loader are already installing. Wait for that one to finish.
  • The pack file itself is broken. Try another version of the pack, or install its files by hand into a blank instance (jar in mods/, configs in config/).

If the failure happened after the pack was working, you should still have the previous version: a rebuild hides the old pack marker and restores it when the install does not finish, and old jars are pruned only after the new ones are on disk.

For the actual error text, open Cubeon Doctor with the launcher log, or ask on the Discord and paste the last few lines.

Adding your own mods to a pack

You can. It is the most common way people break a pack, so do it one mod at a time:

  1. Add a single mod that matches the pack's Minecraft version and loader.
  2. Launch and play for a minute. If it works, keep it; if it crashes, switch it off again.
  3. Repeat. When something breaks, the last mod you added is the one to blame.

Two caveats worth knowing before you start: a pack update may change the mods your addition depended on, and adding a second copy of a library the pack already ships is a reliable crash. Check & repair finds the duplicate case.
